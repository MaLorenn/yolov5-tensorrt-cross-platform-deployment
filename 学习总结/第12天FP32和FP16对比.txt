第12天：参数实验总结

一、实验内容

本次完成以下两组参数实验：

1. TensorRT FP32 与 FP16 对比
2. Jetson Nano MAXN 与 5W 功耗模式对比

取消以下实验：

* 不同模型输入尺寸
* 不同摄像头分辨率

二、FP32 与 FP16 纯推理对比

测试工具：

trtexec

输入尺寸：

640 × 640

FP32结果：

* Engine大小：14 MB
* GPU平均推理延迟：57.63 ms
* Host平均延迟：58.93 ms
* 吞吐率：16.97 qps

FP16结果：

* Engine大小：7.1 MB
* GPU平均推理延迟：46.61 ms
* Host平均延迟：47.91 ms
* 吞吐率：20.87 qps

对比结论：

* FP16 Engine大小减少约49%
* GPU推理延迟降低约19.1%
* 吞吐率提升约23.0%
* Jetson Nano虽然没有Tensor Core，但FP16仍能获得一定纯推理性能提升

三、FP32 与 FP16完整流水线对比

测试程序：

四阶段无界面多线程流水线

队列设置：

* 采集队列容量：1
* 预处理队列容量：1
* 结果队列容量：1
* 队列满时丢弃旧数据
* 测试处理帧数：300帧

FP32结果：

* 平均FPS：11.23
* 平均预处理耗时：64.28 ms
* 平均推理耗时：64.37 ms
* 平均后处理耗时：19.34 ms
* 平均端到端延迟：257.88 ms
* 处理比例：38.17%

FP16结果：

* 平均FPS：11.31
* 平均预处理耗时：64.39 ms
* 平均推理耗时：63.54 ms
* 平均后处理耗时：18.84 ms
* 平均端到端延迟：256.14 ms
* 处理比例：38.46%

对比结论：

* FP16完整流水线FPS仅提升约0.7%
* 推理耗时降低约1.3%
* 端到端延迟降低约0.7%
* 完整系统性能提升远小于trtexec纯推理测试结果

原因分析：

完整流水线不仅包含TensorRT推理，还包括摄像头采集、CPU预处理、CPU与GPU数据传输、后处理和线程同步。

当前预处理耗时与推理耗时都约为64 ms，说明系统瓶颈并不只在GPU推理阶段。因此，单独优化模型计算精度对最终系统FPS的提升有限。

四、不同功耗模式对比

测试精度：

FP32

MAXN模式结果：

* 平均FPS：11.23
* 平均预处理耗时：64.28 ms
* 平均推理耗时：64.37 ms
* 平均后处理耗时：19.34 ms
* 平均端到端延迟：257.88 ms
* 处理比例：38.17%

5W模式结果：

* 平均FPS：5.91
* 平均预处理耗时：95.30 ms
* 平均推理耗时：90.76 ms
* 平均后处理耗时：62.06 ms
* 平均端到端延迟：411.50 ms
* 处理比例：19.99%

对比结论：

* 5W模式下FPS下降约47.4%
* 推理耗时增加约41.0%
* 预处理耗时增加约48.3%
* 端到端延迟增加约59.6%
* 处理比例由38.17%下降至19.99%

5W模式不仅限制GPU频率，也会限制CPU性能，因此预处理、推理和后处理均明显变慢。

对于当前YOLOv5n四阶段实时检测程序，MAXN模式更适合作为正式运行模式。

五、最终结论

1. FP16可以显著减小TensorRT Engine文件大小，并提升纯GPU推理性能。

2. 在完整实时检测流水线中，FP16带来的FPS提升很小，说明系统瓶颈还包括CPU预处理、数据传输、后处理和线程同步。

3. Jetson Nano的5W模式会明显降低系统整体性能，不适合当前实时检测任务。

4. 当前推荐运行配置为：

* 功耗模式：MAXN
* TensorRT精度：FP16
* 模型输入尺寸：640 × 640
* 摄像头分辨率：640 × 480
* 四阶段多线程流水线
* 队列容量：1
* 队列满时丢弃旧帧

5. 当前最适合继续优化的方向不是继续调整模型精度，而是优化CPU预处理、后处理和CPU-GPU数据传输过程。
